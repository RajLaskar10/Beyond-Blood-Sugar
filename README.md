- **R** ≥ 4.2.0 and **RStudio** (recommended)
- The following R packages are **automatically installed** by `00_setup.R` if missing:

| Package | Purpose |
|---------|---------|
| `tidyverse` | Data manipulation and ggplot2 |
| `caret` | Train/test splits, CV, confusion matrix |

| `corrplot` | Correlation heatmaps |
| `scales` | Label formatting in ggplot |
| `knitr` | Tables in RMarkdown |
| `kableExtra` | Styled tables in RMarkdown |
| `broom` | Tidy model output extraction |

## Setup Instructions

### Step 1 — Clone the repository

```bash
git clone https://github.com/RajLaskar10/Beyond-Blood-Sugar.git
cd Beyond-Blood-Sugar
```

### Step 2 — Open the RStudio project

Open `DS5110_Diabetes_Project.Rproj` in RStudio. This sets the working directory to the repo root automatically — required for all relative paths to resolve correctly.

### Step 3 — Obtain the raw data files

> ⚠️ The raw CSV files are **not tracked by git** (too large). You must obtain them separately and place them in `data/raw/`.

**Contact Raj Laskar** for access to the shared Google Drive folder, or request the files directly.

Place these three files in `data/raw/`:

| File | Rows | Size | Description |
|------|------|------|-------------|
| `LLCP2014_model.csv` | 431,877 | ~58 MB | CDC BRFSS 2014 — cleaned |
| `LLCP2022_model.csv` | 305,922 | ~43 MB | CDC BRFSS 2022 — cleaned |
| `LLCP_combined.csv` | 737,799 | ~57 MB | Previous partial combine — do not use for modeling |

Your `data/raw/` directory should look like this after placing the files:

```
data/raw/
├── LLCP2014_model.csv    ← required
├── LLCP2022_model.csv    ← required
├── LLCP_combined.csv     ← required (used only in audit step)
└── README.md             ← tracked by git
```

### Step 4 — Load the environment

Run this once from the RStudio console (or at the top of any script):

```r
source("scripts/00_setup.R")
```

This will:
- Auto-install any missing packages
- Define path variables (`PATH_RAW`, `PATH_PROC`, `PATH_FIG`, `PATH_TABLES`, `PATH_MODELS`)
- Set `SEED <- 42` and call `set.seed(42)`
- Load the project color palette

## Running the Pipeline

Scripts are numbered and **must be run in order** from the repo root.

| Script | Phase | What it does | Output |
|--------|-------|-------------|--------|
| `00_setup.R` | Setup | Loads packages, defines paths/seed/colors | Environment |
| `01_data_audit.R` | Phase 1 | Audits 2014, 2022, and combined CSVs; posts findings | Console output |
| `02_harmonize_verify.R` | Phase 2 | Renames columns, recodes income tiers, row-binds, validates | `data/processed/combined_verified.csv` |
| `03_split_data.R` | Phase 4 | 80/20 stratified train/test splits for all 3 datasets | 6 CSVs in `data/processed/` |

> Scripts for Phases 3 and 5–9 (EDA, modeling, evaluation, analysis) are being added as work progresses.

**Quick start — run the full data pipeline:**

```r
source("scripts/00_setup.R")
source("scripts/01_data_audit.R")
source("scripts/02_harmonize_verify.R")
source("scripts/03_split_data.R")
```

After this, `data/processed/` will contain all 7 generated files (combined + 6 splits).

**To knit the final report** (once `report/final_report.Rmd` exists):

```r
rmarkdown::render("report/final_report.Rmd")
```

## What Is and Isn't Tracked by Git

| Content | Tracked? | How to get it |
|---------|----------|---------------|
| Scripts (`scripts/*.R`) | ✅ Yes | In repo |
| Documentation (`docs/`, `data/data_dictionary.md`) | ✅ Yes | In repo |
| Output figures (`outputs/figures/`) | ✅ Yes | In repo (generated by EDA/viz scripts) |
| `data/raw/*.csv` | ❌ No | Obtain from shared Drive (see Step 3) |
| `data/processed/*.csv` | ❌ No | Run `02_harmonize_verify.R` + `03_split_data.R` |
| `outputs/models/*.rds` | ❌ No | Run modeling scripts (Phases 5–7) |
| `outputs/tables/*.csv` | ❌ No | Run evaluation scripts (Phase 6) |
| `.Rhistory`, `.RData` | ❌ No | R session files — not needed |

## Git Workflow

- **Never commit directly to `main`** — always use a feature branch
- **Branch naming:** `<owner>/<phase>-<short-description>`  
  e.g., `raj/phase1-data-audit`, `gaurav/phase5-logistic-regression`
- **Commit format:** `[Phase X] Short description`  
  e.g., `[Phase 5] Train LR model on 2014 data`
- **PRs:** open against `main`, assign a reviewer, move to "In Review" on the project board

See `CLAUDE.md` for full coding standards and `docs/` for detailed workflow references.
